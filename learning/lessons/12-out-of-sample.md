## 1. 看起来很好的结果，可能只是挑出来的

在同一历史区间里试很多参数、标的和起止日期，再只展示最好的一次，结果可能主要反映挑选。数据越少、尝试越多、规则越复杂，越需要警惕。

“我没有用机器学习”不能排除过拟合。人工反复改参数也在学习同一段历史。

本课的目标是事先规定怎样接受或否定假设，以及怎样留下没有被反复使用的检验机会。

## 2. 三类数据分别做什么？

| 区间 | 用途 | 不应做什么 |
| --- | --- | --- |
| 训练/开发段 | 理解数据、提出规则、估计需要的参数 | 用未来字段或未来样本决定过去信号 |
| 验证段 | 比较预先登记的少量候选，选择方案 | 把每次改动都当作全新独立试验 |
| 最终测试段 | 对冻结方案做一次正式评估 | 看见结果后调参，再称原测试段仍然独立 |

时间序列通常按先后划分，不应随意打乱。学习均值、标准化参数或缺失值处理规则，也需要限制在当时可见的开发数据内。

“60%/20%/20%”只是示例比例，不是万能配置。数据应覆盖足够时间、交易次数和不同市场环境；12行教学数据不足以做可信的策略有效性检验。

## 3. Python：时间边界与信息隔离

下面用1000个编号观察点演示分段，没有证券收益，也没有实际训练模型。假设每个样本的结果依赖后面2期，临近边界的样本可能把结果延伸到下一区间，因此从前一区间末尾剔除2个观察点。

```python
n = 1000
horizon = 2
split1, split2 = 600, 800

train = list(range(0, split1 - horizon))
validation = list(range(split1, split2 - horizon))
test = list(range(split2, n))
# 真正评分时，最后2期在当前数据尾部还没有完整未来结果。
test_scored = [i for i in test if i + horizon < n]

assert max(train) + horizon < min(validation)
assert max(validation) + horizon < min(test)
assert not set(train) & set(validation)
assert not set(validation) & set(test)
assert max(test_scored) + horizon < n

for name, block in [("开发", train), ("验证", validation),
                    ("最终测试", test), ("有完整标签的测试", test_scored)]:
    print(name, "范围", block[0], "至", block[-1], "数量", len(block))
```

预期范围为：开发0—597，共598点；验证600—797，共198点；最终测试800—999，共200点；当前可评分测试800—997，共198点。

本例的2期隔离来自人为设定的未来结果跨度。真实策略若持仓区间重叠或标签跨度不固定，需要更仔细处理，不能统一照搬2期。

滚动特征在测试段开始时读取以前的历史窗口，通常符合信息顺序；用测试段的未来值来补训练段，则不符合。

## 4. 从一次划分到滚动验证

可以用“此前的数据开发、紧接着的一段验证”的方式向前推进。每一折都只能看到该时点之前的信息，记录当时选出的参数与后续结果。

要注意：多次滚动验证也会被研究者用于选择规则，不能把所有反复查看的验证区间重新包装成最终未见测试。还需处理跨边界持仓、预热窗口与成本。

官方背景：[scikit-learn 的时间序列交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html#time-series-split)，查阅日期2026-10-23。当前练习只需Python标准库，不要求安装scikit-learn。

## 5. 一张最小研究记录

把下面字段填入自己的研究说明，未知就写待确定：

| 字段 | 写什么 |
| --- | --- |
| 假设及失效条件 | 预期现象、为什么可能存在、什么结果会否定它 |
| 数据版本 | 标的、来源、范围、时区、复权、原始文件校验值 |
| 候选 | 预先限定参数与候选数量，保留失败版本 |
| 成交与成本 | 信号时点、成交时点、费率、滑点、异常处理 |
| 比较方法 | 事先选定基准、净收益、回撤、换手和暴露 |
| 数据划分 | 开发、验证、最终测试的时间边界与隔离规则 |
| 冻结记录 | 冻结日期和仓库提交号；冻结前不能填写“已经冻结” |
| 实际结果 | 所有候选结果、最终选择原因和局限 |
| 决定 | 继续研究、修改假设或放弃；不得只保留盈利方案 |

不要先编一张漂亮的结果表，再去找支持它的数据。修改假设后应另留版本，并承认此前看过的测试数据已经影响研究。

## 6. 实践与自测

- 给第11课的规则写一份研究登记。参数、标的和真实数据未知的部分标“待确定”，教学回测不要标成实盘验证。
- 把horizon从2改成5，重新检查每个分段边界。
- 假设方案A开发表现最好、验证明显变差；方案B两段稳定但收益较低。应按事先约定的指标和风险条件决策，不能事后发明一套指标保证A获胜。

1. 测试集看过之后还能用于理解失败原因吗？
2. 用它改完规则后，还能把同一测试集称为独立最终测试吗？
3. 冻结规则后，一次样本外盈利是否足以直接进入实盘？
